# QA-BrainTumor-VLM-UCSF

Benchmarking Vision-Language Models (VLMs) on clinical brain tumor MRI visual question answering (VQA), built for the UCSF-PDGM dataset on HPC (SLURM).

## Overview

This repo provides an end-to-end pipeline for:

1. **Dataset Creation** — Generating 4-option multiple-choice QA pairs from the UCSF-PDGM brain MRI dataset
2. **Model Inference** — Running deterministic VQA inference across 5 model architectures
3. **Experiment Orchestration** — Centrally managing all experiments via a single JSON config with intelligent SLURM job scheduling
4. **Evaluation** — Multi-stage accuracy evaluation with multi-run averaging and contrastive error analysis
5. **Human Baseline** — A Tkinter GUI for clinician QA evaluation

## Models Benchmarked

| Model | Type | Input | Adapter Key |
|-------|------|-------|-------------|
| **MedGemma 1.5 (4B-IT)** | Generative VLM | 2D PNG slices (multi/single/blank) | `medgemma` |
| **Med3DVLM (Qwen 2.5-7B)** | Generative VLM | 3D NIfTI volumes (FLAIR) | `med3dvlm` |
| **Qwen 2.5 (7B-Instruct)** | Text-only LLM | Question text only (no images) | `qwen` |
| **MedImageInsight** | Contrastive Embedding (CLIP-style) | 2D PNG slices | `medimageinsight` |

All generative models use deterministic decoding (`do_sample=False`, `temperature=0`).

MedImageInsight is not a generative model — it performs zero-shot classification by computing cosine similarity between image embeddings and text embeddings of each answer option, then picks the highest-scoring option.

## Experiment Orchestrator

The orchestrator replaces manual management of individual SLURM scripts with a single `experiment.json` config file.

### Configuration Hierarchy

Settings inherit: **global → model → test** (most specific wins).

```
experiment.json
├── global                    # Shared defaults (runs_per_experiment, SLURM resources, paths)
├── environments              # How to activate each model's environment
│   ├── conda_dynamic         # Grep conda env list dynamically
│   ├── static_path           # Hardcoded python path + LD_LIBRARY_PATH
│   └── venv                  # source activate a virtualenv
└── models
    └── MedGemma1.5           # Shared: model_path, image_dir, environment
        └── tests
            ├── multi_slice        # Uses multi_slice variant script
            ├── blank              # Overrides image_path for control
            └── multi_slice_shuffled  # Overrides qa_path for reshuffled
```

### Usage

```bash
# Run all enabled experiments
python experiment_orchestrator/run_experiments.py

# Preview all jobs that would run (no files generated, no submission)
python experiment_orchestrator/run_experiments.py --list

# Generate sbatch files but don't submit (dry run)
python experiment_orchestrator/run_experiments.py --dry-run
```

**Filtering by model**
```bash
# Run only one model
python experiment_orchestrator/run_experiments.py --model MedGemma1.5

# Run two models
python experiment_orchestrator/run_experiments.py --model MedGemma1.5 Qwen2.5

# Skip a model (run everything else)
python experiment_orchestrator/run_experiments.py --exclude-model LLaVA-Med
```

**Filtering by test name**
```bash
# Run only the human benchmark across all models
python experiment_orchestrator/run_experiments.py --test human

# Run both the standard and shuffled single-slice tests
python experiment_orchestrator/run_experiments.py --test single_slice single_slice_shuffled

# Skip human tests (run all other tests for all models)
python experiment_orchestrator/run_experiments.py --exclude-test human
```

**Filtering by variant type**
```bash
# Run only blank (control) tests across all models
python experiment_orchestrator/run_experiments.py --variant blank

# Skip blank tests
python experiment_orchestrator/run_experiments.py --exclude-variant blank
```

**Combining filters** — all allow-list flags compose with AND; deny-list always wins:
```bash
# MedGemma, all tests except human
python experiment_orchestrator/run_experiments.py --model MedGemma1.5 --exclude-test human

# All models, only single_slice variant, skip LLaVA-Med
python experiment_orchestrator/run_experiments.py --variant single_slice --exclude-model LLaVA-Med
```

### Local Runner (no SLURM)

`run_local.py` is an alternative entrypoint for running the same experiments **without a SLURM cluster** — on a laptop, VM, or any machine where you can run the testing scripts directly.

It accepts the **exact same filter flags** as `run_experiments.py` so you can use identical invocations.

```bash
# Run all enabled experiments sequentially
python -m experiment_orchestrator.run_local

# Preview matching jobs without running
python -m experiment_orchestrator.run_local --list

# Run only the OpenAI/API tests (CPU, no GPU needed)
python -m experiment_orchestrator.run_local --model GPT5Mini

# Run a specific test across all models
python -m experiment_orchestrator.run_local --test human

# Run 2 jobs in parallel (useful for API-bound models)
python -m experiment_orchestrator.run_local --jobs 2

# Dry-run: print commands without executing
python -m experiment_orchestrator.run_local --dry-run --model MedGemma1.5
```

| Feature | `run_experiments.py` | `run_local.py` |
|---|---|---|
| Execution | SLURM (`sbatch`) | Direct subprocess |
| Concurrency | SLURM queue | `--jobs N` thread pool |
| Environment | conda/venv activation in sbatch | Current active environment |
| GPU allocation | `#SBATCH --gres=gpu:N` | None (use whatever is available) |
| Filter flags | `--model --test --variant --exclude-*` | Same |
| `--list` / `--dry-run` | ✓ | ✓ |

> **Note on environments**: `run_local.py` uses the Python interpreter it is invoked with (`sys.executable` by default, overridable via `--python /path/to/python`). Activate the correct conda environment before running, or pass `--python $(conda run -n myenv which python)`.


1. The orchestrator resolves `experiment.json` into a flat list of jobs (model × test × run)
2. Each job gets a generated `.sbatch` file in `generated_slurm/`
3. The `SlurmScheduler` submits jobs up to `max_concurrent_jobs` (default: 4)
4. It polls `squeue`/`sacct` every 30 seconds, submitting new jobs as slots open
5. The orchestrator runs on a **CPU node** (login or lightweight SLURM job)

| Type | How it works | Used by |
|------|-------------|---------|
| `conda_dynamic` | Greps `conda env list` for the named env at runtime | MedGemma, Qwen |
| `static_path` | Hardcoded absolute python path + optional `LD_LIBRARY_PATH` | Med3DVLM |
| `venv` | `source activate` a virtualenv | MedImageInsight |

### Adding a New Model

The central tenet of the orchestrator is the **Adapter Pattern**. To add a new model, you need to write a script that can run the model, write an adapter that constructs the CLI arguments for it, and then register both in the central config.

**Step 1: Write the testing script**
Create your script in `testing_scripts/` (e.g., `QA_testing_NewModel.py`).
* **CLI Requirements**: It must accept `--qa_path`, `--output_path`, `--model_path`, and an image path argument (`--image_dir` or `--image_path`).
* **Output Requirements**: It must save the results as a CSV to `--output_path` containing the exact same number of rows as `--qa_path` and a column named `predicted_answer` formatted like `1) Answer Text`.

**Step 2: Create an Adapter**
Create a new python file in `experiment_orchestrator/adapters/new_model.py`. Inherit from `ModelAdapter` and implement `build_command()` and `validate()`:

```python
import posixpath
from experiment_orchestrator.adapters.base import ModelAdapter
from experiment_orchestrator.config_resolver import ResolvedJob

class NewModelAdapter(ModelAdapter):
    def build_command(self, job: ResolvedJob, project_root: str) -> str:
        script = posixpath.join(project_root, "testing_scripts/QA_testing_NewModel.py")
        args = [
            f"--qa_path {job.qa_path}",
            f"--output_path {job.output_path}",
            f"--model_path {job.model_path}"
        ]
        if job.image_dir:
            args.append(f"--image_dir {job.image_dir}")
        return f"{script} {' '.join(args)}"

    def validate(self, job: ResolvedJob) -> None:
        if not job.image_dir and not job.variant == 'text_only':
            raise ValueError("NewModel requires an image_dir")
```

**Step 3: Register the Adapter**
In `experiment_orchestrator/adapters/__init__.py`, import and add your adapter to the `ADAPTER_REGISTRY` dict:
```python
from experiment_orchestrator.adapters.new_model import NewModelAdapter
ADAPTER_REGISTRY = {
    ...
    "newmodel": NewModelAdapter(),
}
```

**Step 4: Update `experiment.json`**
Add the new environment and model entry:
1. Define the python environment in the `"environments"` block (e.g., `"new_env": {"type": "conda_dynamic", "env_name": "my_env"}`).
2. Create a new model block in `"models"` with `"adapter": "newmodel"` and `"environment": "new_env"`.
3. Specify the `"tests"` list (e.g., `multi_slice`).

## Testing Scripts

Each testing script follows the same interface:

```bash
python QA_testing_<model>.py \
  --qa_path <ground_truth_csv> \
  --output_path <results_output_csv> \
  --model_path <path_to_model_weights> \
  --image_dir <path_to_images>          # or --image_path for blank
```

### Output CSV Format

All testing scripts produce a CSV with these **required columns** for evaluation:

| Column | Description |
|--------|-------------|
| `Assigned ID` | Patient identifier (from ground truth) |
| `Question` | The full multiple-choice question text |
| `predicted_answer` | The model's predicted answer string |
| `<Model>_Reasoning` | The model's reasoning or similarity scores |

> **Important:** The `predicted_answer` column must contain the answer in the format `N) Answer Text` (e.g., `2) High Grade`) for the evaluation script to match it against ground truth.

### Test Variants

| Variant | Description | Image Input |
|---------|-------------|-------------|
| `multi_slice` | 3 orthogonal PNG slices (Axial, Coronal, Sagittal) | `--image_dir` |
| `single_slice` | 1 Axial PNG slice | `--image_dir` |
| `blank` | Blacked-out image (control experiment) | `--image_path` |
| `full_nifti` | Full 3D NIfTI FLAIR volume | `--image_dir` |
| `text_only` | No image input (text baseline) | N/A |
| `reshuffled` | Same as above but with randomized option order | Overrides `--qa_path` |

## Evaluation Pipeline

The evaluation pipeline has 3 stages, run via:

```bash
python evaluation_scripts/eval_answers.py --stages 1 2 3
```

### Stage 1 — Accuracy (`--stages 1`)

- Walks the results directory tree to find all model output CSVs
- Matches each result file to the appropriate ground-truth CSV:
  - `reshuffled_finalized_ucsf_pdgm_pairs.csv` if filename contains "shuffled"
  - `finalized_ucsf_pdgm_pairs.csv` otherwise
- Computes per-model accuracy by matching `predicted_answer` against ground truth
- Outputs:
  - `metrics/Evals.json` — accuracy per test
  - `metrics/<Model>_wrongs.csv` — per-model wrong answers for analysis

### Stage 2 — Aggregate Rights/Wrongs (`--stages 2`)

- Aggregates which questions are missed most/least frequently across all models
- Generates frequency histograms and exports ranked CSVs
- Outputs:
  - `metrics/Top_wrong_figure.png` / `Top_wrong.csv`
  - `metrics/Top_right_figure.png` / `Top_right.csv`

### Stage 3 — Multi-Run Averaging (`--stages 3`)

- Groups results by model type and base test name (stripping `_runN` suffixes)
- Computes mean accuracy across runs for each test variant
- Computes overall model-level mean accuracy
- Outputs:
  - `metrics/Averaged_Evals.json` — per-model and per-test averaged accuracies

### Requirements for Evaluation

The evaluation script expects:

1. **Results directory structure:** `<qa_path>/<ModelName>/<test_results>.csv`
2. **Ground truth CSVs** in `<answer_dir>/`:
   - `finalized_ucsf_pdgm_pairs.csv` (default order)
   - `reshuffled_finalized_ucsf_pdgm_pairs.csv` (shuffled order)
3. **Result CSV columns:** Must contain `predicted_answer` and match the row count of ground truth
4. **Naming convention:** Multi-run files must use `_runN` suffix (e.g., `multi_slice_results_run1.csv`)
5. **Dependencies:** `pandas`, `matplotlib`, `seaborn`

### Question Format

All questions are **4-option multiple choice** in the format:
```
<Question stem> 1) Option A 2) Option B 3) Option C 4) Option D
```

Options are extracted using the regex: `re.split(r"([0-5]\))", question)`

## Configuration

All scripts and the orchestrator read paths from a single `config.yaml` file that you create locally from the provided example. This file is **gitignored** — it is never committed.

### Setup

```bash
cp config.example.yaml config.yaml
# Then edit config.yaml with your paths (see below)
```

### Required Fields

These are the fields you must set before anything will run. Everything else either has sensible defaults or is only needed for optional pipeline stages.

| Field | What it points to |
|---|---|
| `project_root` | Absolute path to the cloned repo on your machine / cluster |
| `qa_path` | Main QA dataset CSV (`Assigned ID`, `Question`, `Answer` columns) |
| `reshuffled_qa_path` | Answer-order-randomised version of the QA dataset (for bias testing) |
| `output_base` | Root directory where all model result CSVs are written |
| `slice_dir` | Root directory containing per-patient `<pdgm_id>/Axial.png` 2D slices |
| `blank_png` | Path to a blacked-out PNG used as the control/blank experiment image |

### Minimal `config.yaml`

```yaml
# ── Required ──────────────────────────────────────────────────────────────────

output_base: /path/to/output

slice_dir: /path/to/2D_slices          # per-patient Axial.png dirs

# ── Only needed for cluster / GPU model runs ──────────────────────────────────

nifti_root:   /scratch/user/.../UCSF-PDGM-v5

models_base: "{project_root}/models"
medgemma_model_path:       "{models_base}/medgemma-1.5-4b-it"
```

## Running on the Cluster (SLURM)

> **Important**: Always submit the orchestration script **from inside the project root**. SLURM sets `SLURM_SUBMIT_DIR` to wherever `sbatch` was called, and the script uses this to locate `config.yaml` and `run_experiments.py`.

```bash
# On the cluster
cd /scratch/group/.../QA-BrainTumor-VLM-UCSF-
git pull

# Dry-run first to verify all paths resolve correctly
python experiment_orchestrator/run_experiments.py --list

# Submit the orchestrator as a SLURM job
sbatch slurm_scripts/sbatch_run_orchestration

# Monitor
squeue --me
tail -f ~/logs/Orchestration_<jobid>.out
```

You can pass any filter flags through to the orchestrator via `$@`:

```bash
# Only run MedGemma
sbatch slurm_scripts/sbatch_run_orchestration --model MedGemma1.5

# Skip human tests
sbatch slurm_scripts/sbatch_run_orchestration --exclude-test human
```

After all jobs complete:
```bash
python evaluation_scripts/eval_answers.py --stages 1 2 3
```
